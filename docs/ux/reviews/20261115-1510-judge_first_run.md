## 판정: **반려(P0 3건)** · 첫 실행 3초 판독 점수 **4 / 10**

기능 면에서는 숨은 길게 누르기 진입을 없앴고, 개인/시연 데이터를 따로 보존하며, 신호가 null일 때 영구 잠금되지 않게 했고, 재기준 경로도 생겼다. 엣지케이스 처리 자체는 잘 됐다.

하지만 화면 면에서는 **진입점이 시스템 디버그 바처럼 보이는 앱 밖 상단 띠에 약 12sp 글씨로 놓여 있다.** 첫 화면에는 앱이 무엇을 하는지 말해 주는 문장이 없다. 심사관은 3초 동안 "세 가지만 알면 시작할 수 있어요"와 날짜 입력칸만 본다. 결국 직접 계약을 입력하기 시작할 가능성이 높고, 그러면 0km·첫날 상태라 비용 가치를 보지 못한다.

## P0

**P0-1. 첫 화면에서 앱의 정체와 시연 진입이 보이지 않는다.** (`01_first_install.png`)
- 현상:
  - "시연 데이터로 둘러보기"는 짙은 회색 띠 위의 작은 보라색 알약 버튼이다. 높이 약 30dp, 글자 약 12sp로 원칙 기준(76dp·24sp)에 크게 못 미친다. 앱 테마 밖에 있어서 Pleos 시스템 UI나 개발용 도구로 읽힌다.
  - 옆의 "시연 설정"은 더 작고 대비도 낮다.
  - 앱이 무엇을 하는지 설명하는 한 줄이 없다. "30초 시작 · 1/3"은 과정 설명일 뿐이다.
- 수정안: 온보딩 첫 화면 상단을 **두 갈래 선택 히어로**로 바꾼다.
  ```
  남은키로
  장기렌트·리스 약정거리를, 매주 목표와 만기 비용(원)으로 보여 줘요        ← 24~30sp 한 줄
  ┌─────────────────────────────┐ ┌─────────────────────────────┐
  │ ▶ 예시로 둘러보기  [모의]      │ │ 내 계약으로 시작              │
  │ 김 대리 · 만기 정산 약 24만 원 │ │ 만기일·약정·단가 3가지, 30초 │
  └─────────────────────────────┘ └─────────────────────────────┘
  ```
  - 두 카드 모두 높이 120dp 이상, 제목 30sp, 앱 테마(primary/secondary) 버튼으로 만든다. '예시로 둘러보기'를 primary로 둔다. 심사관과 첫 사용자 모두에게 가치를 먼저 보여 주기 위해서다.
  - 예시 카드 안에 홈 막대 썸네일(사용 → 약정 → 초과 +24만)을 작게 넣으면 3초 안에 'km → 원' 앱임을 알 수 있다.
  - '시연 설정'(페르소나 선택)은 상단 띠에서 빼고, 시연 모드 안의 [모의] 칩 메뉴로 옮긴다.

**P0-2. 시연 중 표시와 '내 데이터로 돌아가기'가 너무 작고 앱 밖에 있다.** (`06_demo_home.png`, `09_window_resize.png`)
- 현상: "내 데이터로 돌아가기 · 현재 [모의]"가 약 12sp 알약 버튼이다. 차량 터치 기준에 미달하고, 지금 보는 숫자가 모의라는 사실이 눈에 띄지 않는다. 앱 안 우측 상단 '모의' 배지도 22sp 테두리뿐이다.
- 수정안: 앱 헤더 안에 **시연 모드 칩**(높이 76dp, 24sp, 채움 배경)을 둔다. 문구: "[모의] 김 대리 예시 보는 중 · 내 데이터로". 누르면 확인 없이 즉시 전환한다(개인 데이터가 따로 보존되므로 안전). 반쪽 창에서도 칩이 줄바꿈 없이 1줄로 보이게 한다.

**P0-3. 급증 보류 화면의 해결 행동이 잘못 배치돼 있다.** (`04_spike_hold.png`)
- 현상:
  - 카드 안 주 버튼 "차량 값 다시 조회"는 다시 조회해도 같은 20,000km가 와서 보류가 반복된다. 실제 해결 방법인 "계기판 기준 다시 설정"은 앱 밖 작은 상단 띠에 있다.
  - "이 간격의 허용 증가량 0 km"(1초 × 250km/h ≈ 0.07km가 반올림됨)는 앱이 고장 난 것처럼 보인다.
  - "마지막 수신 2026-11-14T21:45:23.016665"는 날짜·시각 원문(ISO) 그대로 노출된다.
  - 상단 띠의 "첫날 예상 비용은 아직 확정할 수 없어요"는 보류 상태와 무관한 문구다.
- 수정안: 카드 안에 두 갈래 행동을 둔다.
  ```
  계기판이 1초 만에 0 → 20,000 km로 바뀌었어요
  [주행으로 세지 않았어요]   ← 상태 한 줄
  ① 잠깐 오류였다면     [다시 확인]          (secondary)
  ② 계기판·차가 바뀌었다면 [20,000 km를 새 기준으로] (primary)
     → 지금까지 기록은 그대로, 앞으로 여기서부터 셉니다
  ```
  - 허용 증가량은 소수 1자리로 "0.1 km 이내"처럼 쓰거나 행을 지운다. 시각은 "오후 9:45"처럼 쓴다.
  - 재기준 확인 창 문구에는 "20,000km는 주행 거리로 더하지 않아요"를 반드시 넣는다.
  - 보류 화면에서는 첫날 안내 띠를 숨긴다.

## P1

| # | 발견 | 수정안 |
|---|---|---|
| P1-1 | 계약 생성 직후 첫날에 공제 질문 시트가 바로 뜬다(`03`). 예측도 없는 시점에 홈을 가리며, '첫 만기 정산 진입 시 1회'라는 원칙과 다르다 | 공제 질문은 7일 뒤 정산 예측이 처음 표시될 때 1회만 띄운다 |
| P1-2 | 첫날 홈 "계약 페이스와 지금까지 주행 비교 **0 km** · 계약 페이스보다 덜 탔어요"(`05`)는 0인데 '덜 탔다'는 모순이다 | 사용 0km인 첫날에는 "오늘부터 기록해요"로 바꾸거나 카드를 숨긴다 |
| P1-3 | 시연 홈(`06`)은 아직 구 디자인이다(우측 카드 7줄, 링 하단 3줄). mockup_v2 D4 반영 전이라 심사관이 처음 보는 홈이 글 중심이다 | mockup_v2 D4(P0 2건 수정 후)를 Compose에 반영하는 작업을 첫 실행 경로와 같은 우선순위로 둔다 |
| P1-4 | 반쪽 창(`09`)에서 홈 제목이 "…약 24만 / 원 예상"으로 단위가 끊겨 줄바꿈된다 | 숫자와 단위를 묶어 줄바꿈을 막는다. 반쪽 창에서는 제목을 짧게 한다("96km 남음 · 만기 약 24만 원") |
| P1-5 | '차량 신호 확인 중' 화면은 캡처가 없어 검토하지 못했다 | 캡처 후 재검토가 필요하다. 요구 사항: 한 줄 상태("기어·주행 제한 신호를 기다리는 중") + [다시 확인] + [예시로 둘러보기] 76dp, 숫자·비용 미표시 |
| P1-6 | 온보딩 날짜가 여전히 YYYY-MM-DD 직접 입력이다. 과거 날짜를 넣어도 '다음' 버튼이 활성으로 보일 수 있다(문서 8번) | 날짜 선택기를 쓰고, 오류 문구를 필드 아래 1줄로 둔다. 버튼 활성 조건은 ViewModel 검증과 같게 한다 |
